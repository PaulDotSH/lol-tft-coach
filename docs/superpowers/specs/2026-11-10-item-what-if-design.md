# Item what-if simulator

Date: 2026-11-10. Status: draft for review. Idea A1 in `docs/ideas.md`.

## Goal

For Buy next and its alternatives, show what each item changes in numbers against
the enemies in this game: "Rabadon's: +14 % to Ahri, +6 % to Malphite · Void Staff:
+8 % / +19 %", and for defensive items the effective-HP change against their damage
mix. Today these choices are scored by tags and a reference penetration gain
(`resists::Targets::gain`); the simulator makes the reason physical.

Stopping condition for v1: numbers shown for Buy next + alternatives, display only,
for every champion with a kit profile, with unit tests on hand-calculated cases. The
item score is not changed in v1 (see "Feeding the score").

## Decisions

| Topic | Decision |
|---|---|
| Ability numbers | A checked-in `crates/coach/kits.toml`, generated by a dev tool from Community Dragon's champion bins and corrected by hand. Nothing new is fetched at runtime. |
| Item passives | A checked-in `crates/coach/item_effects.toml` for the passives that change damage or EHP (about 40 items). Items not listed count by their stats only. |
| What is compared | Relative change (%) of two reference outputs, burst and sustained, per enemy and threat-weighted. Never an absolute "you deal 1,432". |
| Where it runs | `coach::whatif`, pure, inside `game_advice`. |
| Scope | Rift, ARAM, Mayhem. In Mayhem, stat augments are already in my live stats; augment procs are not modelled and the row says so. |

Alternatives considered for ability numbers: Data Dragon spell `vars` (mostly empty
since the tooltip rework), Meraki Analytics JSON (a new third-party source, parsed
from the wiki, sometimes a patch behind), interpreting Community Dragon calculations
at runtime (exact, but damage type and "which calculation is the damage" still need a
hand table, and a parser bug would be invisible in game). A generated file that a
human reads keeps the app's pattern: tuning lives in TOML, parsers are tested on
fixtures.

## Model

### Inputs (all already in `game_advice`)

- My live stats: `snap.my_stats` (AD, AP, attack speed, crit, lethality, % pens,
  haste, max HP, armor, MR) and level. Without `my_stats` there is no what-if.
- Targets: `resists::enemies` gives each enemy's armor and MR. Their HP is added the
  same way: `grow(base.hp, base.hp_per_level, level) + inventory.hp`.
- Weights: the `Targets` list's threat weights (already used for pen notes).

### Kit profile (`kits.toml`)

The numbers in both examples below show the file shape only; the real values come
from the generator and the patch.

```toml
[Ahri]
# base damage by rank, ratios on total AP / bonus AD / total AD / target max HP
[[Ahri.spell]]
key = "Q"
kind = "magic"            # physical | magic | true
base = [40, 65, 90, 115, 140]
ap = 0.50
hits = 2                  # out and back; the return is true damage in game: second entry
cooldown = [7, 7, 7, 7, 7]
[[Ahri.spell]]
key = "R"
kind = "magic"
base = [60, 90, 120]
ap = 0.35
hits = 3
cooldown = [130, 115, 100]
[Ahri.autos]
on_hit = 0.0              # share of damage from on-hit effects (traits.on_hit as default)
crit = false
```

- Ranks come from `GameSnapshot.my_abilities` (added by the next-skill-point spec);
  without it, ranks follow the lolalytics skill order for my level.
- A champion without a profile falls back to a class profile (mage: one AP-ratio
  rotation; marksman: autos with crit; and so on) and the row is marked "rough".

### Item effects (`item_effects.toml`)

Stats come from Data Dragon as today. This file adds only what stats miss:

```toml
[3089]  # Rabadon's Deathcap
ap_mult = 1.30
[3031]  # Infinity Edge
crit_damage = 0.40
[3153]  # Blade of the Ruined King
on_hit_current_hp = 0.08   # ranged; melee 0.12 handled by attack_range
[6653]  # Liandry's
burn_max_hp = 0.06
amp_in_combat = 0.06
```

Field set, each optional: `ap_mult`, `crit_damage`, `amp` (all damage), `amp_vs_hp`
(Giant Slayer style, scaled by the target's HP over mine), `on_hit_flat`,
`on_hit_ap`, `on_hit_current_hp`, `burn_max_hp`, `proc_flat` / `proc_ap` /
`proc_ad` with `proc_cd` (Sheen family, Luden's), `shield`, `ehp_mult_physical` /
`ehp_mult_magic` (Randuin's, Force of Nature at full stacks). Checked each patch
together with `modes.toml`.

### Buying an item

`with_item(stats, item, owned)`:

- adds the item's stats, minus the stats of owned components it consumes (the
  `items::parts` walk already used for remaining cost);
- AD from items is bonus AD; attack speed is a share of the champion's base attack
  speed (`BaseStats.attack_speed`, as `items::as_gain` does);
- pens combine like `resists::Pen::plus`; `ap_mult` applies to total AP after adding;
- crit is capped at the mode's cap (`modes::rules`), so overcap shows as no gain.

### Two outputs

- **Burst**: every spell once at its rank plus `BURST_AUTOS` (2) attacks, with procs
  that have no cooldown limit once.
- **Sustained** over `SUSTAIN_S` (10 s): attacks at my attack speed with average
  crit, each spell cast `1 + floor(SUSTAIN_S / (cooldown / (1 + haste / 100)))`
  times, procs by their cooldown, burns for their duration.

Each damage part goes through `100 / (100 + resist after pen)` for its kind against
each target. % HP parts use the target's HP estimate. The what-if value for a target
is `damage_with_item / damage_now − 1`.

Which of the two outputs leads is the champion's `traits.burst` (≥ 0.5: burst).
Both are in the tooltip.

### Defensive side

`ehp(kind) = max_hp × (1 + resist / 100)` already exists in `resists::defense`. The
what-if is the same with the item added, weighted by `Defense.enemy_magic` and
`enemy_true`: "+18 % EHP vs their mix (+31 % vs magic, +0 % vs physical)".

## Output and UI

```text
GameAdvice.what_if: Vec<WhatIf>        // Buy next, then the alternatives
WhatIf { item, damage: f32, per_enemy: Vec<(ChampKey, f32)>, ehp: f32,
         ehp_physical: f32, ehp_magic: f32, rough: bool, note: Option<String> }
```

- `BuyNext.svelte`: after each row's reason, one compact figure: the damage gain for
  damage items ("+9 % dmg"), the EHP gain for defensive ones ("+18 % EHP"), both when
  an item gives both. Hover or the build-path panel shows the per-enemy table.
- Not in the overlay, not spoken.
- Sorting stays the coach's. When the numbers disagree with the order (an
  alternative gains 5 points more damage than Buy next) nothing is reordered in v1;
  the numbers are simply visible.

## Feeding the score (after v1)

Only once the display has been used in real games:

1. `examples/whatif_agree.rs`: for the 30 most played champions, compare the
   simulator's ranking of second and third items with lolalytics' slot win rates
   against tanky and squishy enemy sets. Report agreement.
2. If it agrees (target: the lolalytics-best item is in the simulator's top 3 in
   70 % of cases), replace `Targets::gain`'s reference pen gain in `score_all` with
   the simulated gain, weight in `consts.rs`.

## Errors and gaps

- No profile and no class fallback (new champion): no numbers.
- Conditional kits (stacks, forms, executes) are averaged in the profile by hand; the
  number is a comparison aid, not a damage meter. The UI never shows absolutes.
- Enemy resists are estimates from visible items and levels (runes, shards and
  temporary buffs are unknown), as the pen notes already say with "~".
- Healing, shielding and utility items show no damage or EHP gain: they keep their
  tag-based reason only.

## Work order

1. `tools/kits/gen.py`: Community Dragon bin → draft `kits.toml` (base, ratios,
   cooldowns), one saved bin as a fixture; hand pass over the champions in my match
   history first.
2. `whatif.rs` + `item_effects.toml` + tests; `what_if` on `GameAdvice`.
3. UI figure and table; mock fixture.
4. Agreement example; decide on feeding the score.

## Testing

- Hand-calculated: Rabadon's vs Void Staff for a 400 AP mage against 40 MR and
  150 MR targets (the crossover must sit where the formula says); lethality vs %
  armor pen against 60 and 200 armor; Infinity Edge at 50 % and 100 % crit.
- Properties: more penetration never lowers damage; an item whose stats and effects
  are all zero changes nothing; crit past the cap gains nothing.
- `with_item` subtracts consumed components (Needlessly Large Rod into Rabadon's).
- Every champion key in `kits.toml` and item id in `item_effects.toml` exists in the
  Data Dragon fixture (catches renames per patch).
- Smoke example prints the table for one Rift and one ARAM case.
